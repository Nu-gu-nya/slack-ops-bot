# 1단계 — 기획 (요구사항 정의)

> 코드를 한 줄도 쓰기 전에 이 문서를 먼저 채운다.
> 이 문서의 목적은 완벽한 명세를 쓰는 게 아니라, 나중에 "왜 이렇게 만들었냐"는 질문에
> 답할 수 있는 근거를 남기는 것이다.

---

## 1. 문제 정의

**누가 쓰는가**
부서별로 인턴/팀원을 관리하는 소규모 조직의 관리자, 그리고 그 인턴/팀원들.

**무엇이 불편한가**
- 매일 아침 누가 출근했는지 관리자가 일일이 채널을 보며 확인해야 한다
- 시간대별 업무 진척을 팀원마다 다른 형식으로 보고해서 취합이 번거롭다
- 원문 그대로는 매니저가 여러 명분을 읽고 패턴(누가 자주 지연되는지)을 파악하기 어렵다

**무엇을 해결하는가**
- 스프레드시트에 미리 등록된 근무 계획을 기준으로, 정해진 시각에 근무 예정자를 자동으로 멘션하고
  본인이 스레드 답글로 출근을 확인하게 한다
- 자유 형식으로 입력한 시간대별 업무 보고를 정해진 포맷으로 정리하고, Claude API로 요약해
  매니저에게 다이제스트 형태로 전달한다

> 이 세 문단이 "왜 이 프로젝트를 만드는가"에 대한 답이다.

---

## 2. 유저 스토리

우선순위 P0는 이번 프로젝트의 완성 기준이다. P1, P2는 여유가 있으면 붙인다.
**두 봇 모두 P0만 끝나도 완성된 프로젝트다.** (README.md 참고)

### Bot A — 출근 알림 봇

| ID | 스토리 | 우선순위 |
|---|---|---|
| US-01 | 관리자로서, 오늘 근무 예정인 인턴이 정해진 시각(08:50)에 부서 채널에서 자동으로 멘션되길 원한다 | P0 |
| US-02 | 인턴으로서, 출근하면 멘션된 메시지의 스레드에 댓글만 달면 확인이 끝나길 원한다 | P0 |
| US-03 | 관리자로서, 시트 조회나 슬랙 전송이 실패했을 때 그 사실을 알고 싶다 | P1 |
| US-04 | 관리자로서, 확인 시각이 시트에도 기록되어 나중에 이력을 볼 수 있으면 좋겠다 | P1 |
| US-05 | 관리자로서, 일정 시간 뒤에도 미확인자가 있으면 재알림을 받고 싶다 | P2 |

### Bot B — 업무 보고 다이제스트 봇

| ID | 스토리 | 우선순위 |
|---|---|---|
| US-06 | 팀원으로서, `/report` 명령으로 시간대별 업무 내역(시간/업무/상태)을 입력하고 싶다 | P0 |
| US-07 | 팀원으로서, 입력한 내용이 정해진 포맷("09:00 A업무 (완료)")으로 정리되길 원한다 | P0 |
| US-08 | 매니저로서, 원문이 아니라 Claude가 요약한 다이제스트로 오늘 진척을 한눈에 보고 싶다 | P0 |
| US-09 | 매니저로서, 요약이 실패해도 원문은 반드시 전달받고 싶다 | P0 |
| US-10 | 매니저로서, 보고를 아직 안 한 팀원이 누군지 알고 싶다 | P1 |
| US-11 | 팀원으로서, 일정 시간마다 보고를 잊지 않도록 리마인드를 받고 싶다 | P2 |

## 3. 인수 조건 (Acceptance Criteria)

### US-01 — 근무 예정자 자동 멘션

- [ ] 평일 08:50(Asia/Seoul)에 스케줄러가 실행된다
- [ ] 시트에서 오늘 날짜, 상태가 '결근'이 아닌 행만 대상자로 계산한다
- [ ] 대상자가 없는 부서 채널에는 메시지를 보내지 않는다
- [ ] slackUserId가 비어 있는 행은 멘션 대상에서 제외하고 관리자에게 별도로 알린다
- [ ] 시트 조회가 실패하면 멘션을 보내지 않고 관리자에게 실패 사실을 알린다

### US-02 — 스레드 답글로 출근 확인

- [ ] 멘션 메시지의 스레드에 대상자 본인이 답글을 달면 ✅ 리액션이 붙는다
- [ ] 대상자가 아닌 사람이 같은 스레드에 답글을 달아도 오류 없이 무시된다
- [ ] 같은 사람이 여러 번 답글을 달아도 리액션은 중복되지 않는다

> 실패·예외 케이스까지 정의해야 인수 조건이 완성된다.

### US-06/07 — 업무 보고 입력 및 포맷팅

- [ ] `/report` 실행 시 시간·업무·상태를 여러 줄 입력할 수 있는 모달이 뜬다
- [ ] 상태는 자유 텍스트가 아니라 정해진 값(완료/지연/미착수) 중에서 선택한다
- [ ] 필수 항목이 비어 있으면 제출이 거부되고 어느 항목이 문제인지 표시된다
- [ ] 제출 성공 시 "09:00 A업무 (완료)" 형식으로 정렬되어 조립된다

### US-08/09 — 요약 및 폴백

- [ ] 정상 상황에서는 Claude API가 생성한 요약이 매니저 채널에 전달된다
- [ ] Claude API 호출이 실패(타임아웃/레이트리밋)하면 원문 포맷 그대로 전달되고
      "(자동 요약 실패, 원문 표시)"가 붙는다
- [ ] 어떤 경우에도 보고 자체가 유실되지는 않는다 (요약 실패 ≠ 보고 실패)

## 4. 이번에 만들지 않는 것

| 제외 항목 | 이유 |
|---|---|
| 웹 대시보드 | Slack 자체가 UI. 필요성이 검증되면 별도 확장 단계로 진행 |
| 자체 DB | Google Sheets가 이미 입력 UI + 저장소 역할을 겸함 |
| 시트 확인 시각 back-write | MVP 범위에서 뺌 (동시성까지 다루기엔 시간 대비 이득이 작음, ADR-004) |
| 다중 워크스페이스 지원 | 단일 조직 사용 전제, Socket Mode 특성상도 확장에 안 맞음 |
| GPS/IP 기반 실제 출근 검증 | 스레드 답글은 자기신고 방식. 부정 사용 방지는 이번 범위 밖 |
| 리마인드 넛지(30분 단위) | Bot B는 1회 제출 방식으로 시작. 리마인드는 P2로 남김 |

## 5. 이슈로 쪼개기

이슈 하나의 크기 기준: **반나절 안에 끝낼 수 있는 단위.**

예시 분해:

```
US-01 근무 예정자 자동 멘션
├── #1 [core] Google Sheets 서비스 계정 연동 + 오늘 행 조회
├── #2 [core] 근무 대상자 필터링 로직 + 단위 테스트
├── #3 [bot] 부서→채널 매핑 설정 + 멘션 메시지 발송
└── #4 [bot] node-cron 스케줄 등록 (08:50, 평일)

US-06~09 업무 보고 다이제스트
├── #5 [bot] `/report` 커맨드 + 모달 UI
├── #6 [bot] 모달 제출 파싱 + 포맷팅 + 단위 테스트
├── #7 [core] Claude API 연동 + 요약 프롬프트
└── #8 [core] Claude 실패 시 원문 폴백 처리
```
